## 0. Goal / Non-goals

### Goal (Definition of Done)

Ship **v0.2** single-container image that:

1. Runs **N official `warp-svc` processes** in **proxy mode**, isolated by `STATE_DIRECTORY` + `RUNTIME_DIRECTORY` + per-instance dbus.
2. Exposes **direct SOCKS** per instance and **aggregate SOCKS RR** on `:1080` via existing `warppool aggregate`.
3. Exposes **control API** on `127.0.0.1:9090` with rotate ladder: reconnect → hard re-register.
4. On VPS smoke (side-car ports, not production 1080): N=2, `warp=on`, **often distinct egress IPs**, rotate changes IP at least once in test, kill one backend aggregate still works, docker stats **≤300MiB** within 10min cold.
5. **MIT** original code; **no copy** of ErcinDedeoglu/cloudflare-warp scripts (CC-BY-NC). Behavior reference only.
6. Docs/README state B1 deprecated; v0.2 is primary.

### Non-goals (this plan)

- Replacing live `warp-chen` / cutting over production `1080` on VPS.
- N=5 default on 1C2G.
- Zero Trust / WARP+ license matrix (optional env hooks OK, not required for DoD).
- IPv4-only enforcement (document IPv6 possibility; separate follow-up if business needs v4).
- Keeping B1 binaries in default image (optional `legacy-b1` tag/branch later, not in DoD).
- Forking or vendoring Ercin source.

## 2. Architecture lock (implement exactly this)

```
/entrypoint.sh (PID1)
  for id in 0..N-1:   # serial
    scripts/start-instance.sh $id
      → dbus-daemon (unix:path=/run/dbus-${id}/system_bus_socket)
      → env STATE_DIRECTORY=/data/instances/${id}/state
           RUNTIME_DIRECTORY=/run/warp-${id}
           DBUS_SYSTEM_BUS_ADDRESS=...
         warp-svc --accept-tos
      → warp-cli (same env): registration new if no reg; mode proxy; proxy port $PORT; connect; qlog disable
      → wait probe warp=on on 127.0.0.1:$PORT
  warppool aggregate --listen :1080 --healthy /data/state/healthy.json
  warppool control --listen 127.0.0.1:9090 ...
  health-loop (background)
  supervise: warp-svc death → mark unhealthy + optional restart; N=1 death → container exit ≠0
```

**Ports**

| Role | Container port | Default host map (compose example) |
|------|----------------|-------------------------------------|
| Aggregate SOCKS | 1080 | 127.0.0.1:1080 (prod) / 19080 (smoke) |
| Instance direct | `INSTANCE_PORT_BASE+id` default **40000+id** | 127.0.0.1:40000-40001 or 19100+ |
| Control | 9090 | not published (exec only) |

**Env (v0.2 minimum)**

| Var | Default | Notes |
|-----|---------|-------|
| `WARP_INSTANCES` | 2 | was 1 in B1; v0.2 default 2 |
| `INSTANCE_PORT_BASE` | 40000 | was 11000 |
| `WARP_CONNECT_TIMEOUT` | 45 | daemon ready wait |
| `BOOT_HEALTH_WAIT` | 90 | per-instance probe |
| `REGISTER_STAGGER` / `REGISTER_JITTER_MAX` | 5 / 8 | keep |
| `PARTIAL_REGISTER_POLICY` | degraded | keep |
| `ROTATE_COOLDOWN` | existing | keep |
| `ROTATE_MODE` | `reconnect` | or `hard` |
| `DEREGISTER_ON_SHUTDOWN` | 1 | new |
| `WARP_LICENSE_KEY` | empty | optional single key first version |
| `CONTROL_*` | unchanged | |

## 4. QA scenarios (executable)

### 4.1 QA P1 — N=1

```bash
# build
docker build -t warp-pool:v02-test .

docker rm -f wp1; docker run -d --name wp1 --restart=no \
  -e WARP_INSTANCES=1 \
  -e INSTANCE_PORT_BASE=40000 \
  -p 127.0.0.1:19400:40000 \
  -v wp1-data:/data \
  warp-pool:v02-test

# wait up to 120s
curl -sS --max-time 20 --socks5-hostname 127.0.0.1:19400 https://cloudflare.com/cdn-cgi/trace | tee /tmp/p1.trace
grep -qE 'warp=(on|plus)' /tmp/p1.trace
docker stats --no-stream wp1   # expect ~80-130MiB class
# no NET_ADMIN in compose
docker rm -f wp1; docker volume rm wp1-data
```

**Pass:** warp=on; container no cap_add required; RSS order ~100MiB not ~10MiB.

### 4.2 QA P2 — N=2 + aggregate

```bash
docker run -d --name wp2 \
  -e WARP_INSTANCES=2 \
  -p 127.0.0.1:19080:1080 \
  -p 127.0.0.1:19400-19401:40000-40001 \
  -v wp2-data:/data warp-pool:v02-test
# both directs warp=on
# 8x curl aggregate → prefer ≥2 distinct ip= lines (soft fail if 1: log only)
# docker kill warp-svc of id1 simulation: stop-instance 1; aggregate still warp=on via other
docker stats --no-stream wp2  # ≤300MiB
```

**Pass:** two directs up; aggregate works; stats ≤300MiB; single instance stop does not kill whole container when N=2.

### 4.3 QA P3 — rotate

```bash
IP_BEFORE=$(curl -sS --socks5-hostname 127.0.0.1:19400 https://cloudflare.com/cdn-cgi/trace | awk -F= '/^ip=/{print $2}')
docker exec wp2 curl -sS -X POST 'http://127.0.0.1:9090/rotate?id=0'
sleep 10
IP_AFTER=$(...)
# Pass if IP_AFTER != IP_BEFORE OR reconnect reported success and warp still on
# Second rotate within cooldown → 429
```

**Pass:** at least one of {IP changed, documented reconnect success + still warp=on}; cooldown enforced.

## 6. Risks & mitigations

| Risk | Mitigation |
|------|------------|
| CF rate limit on dual register | stagger+jitter; degraded policy |
| warp-svc memory leak | doc MemoryMax; periodic rotate; N=2 default |
| IPv6-only exits break v4-only clients | note in README; follow-up force-v4 task |
| apt warp package arch/version drift | pin codename; record version in image label |
| Accidental Ercin copy | reviewer checklist: no CC-BY-NC headers; original scripts |
| Smoke hits production ports | fixed 19xxx in tests |
| hard rotate exhausts device slots | DEREGISTER_ON_SHUTDOWN; prefer reconnect |
