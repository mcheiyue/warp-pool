# Plan: warp-pool v0.4 — hardening, hot config, v4 uniqueness

## Goal

Ship v0.4 on top of working v0.3: delivery fixes, less privilege/memory, robust netns, better UI/ops, **config hot-reload**, and **post-rotate pool-wide IPv4 uniqueness**.

## Out of scope

- N>2 soak  
- Metrics/monitoring integrations  
- Richer health probes (latency, forced v6 health fields beyond display)

## Acceptance (summary)

See `docs/pivot-v0.4.md` §4.4 and §5 gates.

- [ ] Push path works; GHCR builds multi-arch or documented amd64+arm64 plan  
- [ ] STATUS/README match reality  
- [ ] Optional non-privileged path documented; smoke on minimal caps if possible  
- [ ] microsocks (or lighter SOCKS) replaces gost if smoke-equal  
- [ ] netns survives container restart without RTNETLINK death spiral  
- [ ] rotate/boot: v4 unique across healthy peers or explicit failure  
- [ ] hot add/remove instance without full container recreate (within published port range)  
- [ ] WebUI: token UX, v4/v6, last_rotate, cooldown, batch rotate, agg status  
- [ ] logs under `/data/logs/`

## Work packages

### WP-A Delivery

- Fix git push (VPS token/SSH or local net)  
- Dockerfile: multi-arch SOCKS binary  
- CI tags; STATUS sync  

### WP-B Runtime

- Caps-only compose probe vs privileged  
- microsocks swap + expose consolidate  
- netns boot cleanup (`umount`/`make-shared`/stale del)  

### WP-E V4 uniqueness (do early)

- `scripts/lib.sh`: `v4_conflicts(id, v4)` against other meta  
- `rotate-instance.sh` / start path: retry restart then hard  
- env: `V4_UNIQUE_RETRIES`, `V4_UNIQUE_HARD_RETRIES`, `V4_UNIQUE_BACKOFF`  
- healthy.json only unique+healthy  
- API fields: `unique`, `attempts`, `v4`; 409 on exhaust  
- short global lock around uniqueness commit  

### WP-D Hot config

- `GET/PUT /config` whitelist  
- `POST /instances`, `DELETE /instances?id=`  
- entrypoint supervisor watches desired N vs running  
- document port publish ceiling  

### WP-C UX

- WebUI enhancements  
- schedule / auto-rotate verify  
- file logs  

## Order

1. WP-A  
2. WP-E  
3. WP-B  
4. WP-D  
5. WP-C  

## File touch map (expected)

| Path | Change |
|------|--------|
| `scripts/lib.sh` | uniqueness helpers |
| `scripts/rotate-instance.sh` | retry/hard on collision |
| `scripts/start-instance.sh` / `ensure` / `health-once` | unique gate |
| `entrypoint.sh` | netns boot; hot N |
| `cmd/warppool/main.go` | API uniqueness + hot config |
| `web/index.html` | UI fields |
| `Dockerfile` / compose / `.env.example` | caps, microsocks, env |
| `docs/*` | pivot-v0.4, ADR, STATUS |

## Rollback

- Uniqueness off via `V4_UNIQUE=0` (legacy v0.3 behavior)  
- Privileged compose fallback  
- gost image tag if microsocks regresses  

## Implementation trigger

User says go on v0.4 → execute WP order; do not start large rewrite without uniqueness design frozen (this plan).
