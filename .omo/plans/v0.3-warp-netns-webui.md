# Plan: warp-pool v0.3 — Warp+netns + WebUI

## Goal

Replace v0.2 WarpProxy multi with **Warp mode per netns** so IPv4 diversity + rotate-by-restart work (as proven by dual caomingjun containers). Keep one-container ops surface: control API + **single-page WebUI**.

## Evidence (do not re-litigate)

- Dual Warp containers: v4 diverse; per-container restart changes that instance v4 only.  
- v0.2 Proxy pool: full container / per-process restart does **not** reliably change v4; often same v4 on both ports.  
- Product priority: one unit to schedule > min memory.

## Acceptance

See `docs/pivot-v0.3.md` §1. Summary:

- [ ] N=2 v4 often distinct (`ipv4.icanhazip.com` via direct ports)
- [ ] rotate id=0 changes that port v4; id=1 stays healthy
- [ ] aggregate :1080 works; unhealthy removed from RR
- [ ] WebUI lists instances + rotate with token support
- [ ] VPS side-car 19xxx smoke; no touch warp-chen :1080

## Gate G0 (BLOCKING — before large rewrite)

**Minimal in-container netns×2 Warp probe** on VPS side-car.

Files (throwaway OK): `scripts/probe-netns-warp.sh` or `/tmp` script.

Steps:

1. One container with `iproute2` + `cloudflare-warp` + NET_ADMIN + tun  
2. `ip netns add wp0 wp1`  
3. Each ns: warp-svc Warp mode + SOCKS  
4. Measure v4 on both; restart wp0 only; measure again  

**Pass:** v4 diversity + wp0 v4 changes.  
**Fail:** stop single-container netns path; implement multi-container backend behind same API/UI (`deploy/compose-multi-warp`).
