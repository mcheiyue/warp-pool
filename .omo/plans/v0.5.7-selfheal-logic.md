# Plan: v0.5.7 自愈逻辑纠偏（P0–P2）

## Goal

消除「同 IP 假成功补丁 + 自动 rotate + 长 start 锁 + 嵌套 health」组合导致的**自杀螺旋**，使池在 CF 常驻同一 anycast（如 `104.28.195.192`）时仍能稳定 ≥N-1 健康，且 manual/guard 出池语义不变。

**非目标**：换 WARP 供应商、改聚合协议、大改 WebUI、下线 `V4_UNIQUE`。

## Evidence（现网 9bfef8e @ 2026-08-18）

| 信号 | 含义 |
|------|------|
| `same v4 … as pre-rotate` ×6 → `v4_collision exhausted` | R2 把 unique 同 IP 也当失败，叠 AUTO 连杀 |
| `start lock timeout` → `all warp-svc dead` → entrypoint exit | flock 盖住整段 start，堵死并行恢复 |
| `/pool members=[]` 而 meta 有 healthy | rotate 嵌套 health-once 写出残缺 backends |
| sticky 钉死 id4 | 不校验 members/healthy |
| manual=`manual` / guard=`guard-l1` / rotate=`drain` | 出池 reason 已可区分；自愈只动 drain |

根因对照见会话梳理：冲突 A–E（R2×R3、R4 范围、health 无单飞、failures 混用、sticky）。

## Constraints

1. 镜像只走 GHCR Actions，禁止 VPS docker build 当发布路径  
2. `exclude_reason=drain` 仅 rotate 可写；heal 不得碰 `manual` / `guard-*`  
3. 客户端只连聚合口；直连/expose 正交  
4. 最小 diff：优先改 shell 策略，少动 Go 控制面

## P0 — 停自杀（必须先做）

### P0.1 收窄「同 IP 当失败」（R2）

**文件**：`scripts/rotate-instance.sh`（`_commit_changed_unique`）

| 现状 | 目标 |
|------|------|
| `cip == baseline_ip` → 一律 return 1 | 仅当 **同 baseline 且 `v4_conflicts`** 才失败 |
| unique 的同 IP 也 hard | **unique 同 IP → commit 成功**（写 history reason=`rotate:same-ip-unique`） |

伪逻辑：

```bash
if [ -n "$baseline" ] && [ "$cip" = "$baseline" ]; then
  if v4_conflicts "$cid" "$cip"; then
    log "same v4 + pool conflict — retry"
    return 1
  fi
  log "same v4 but unique in pool — accept"
fi
# 再走 commit_if_unique / write_meta
```

**验收**：单实例 baseline=195.192、池内无第二人持有该 IP 时，一次 rotate restart **成功返回 0**，不进入 hard 链。

### P0.2 自动 rotate 熔断（R3）

**文件**：`scripts/lib.sh` + `scripts/health-once.sh` + `scripts/rotate-instance.sh`

新增 per-id 状态（文件即可，不进 DB）：

```
/run/warp-pool/rotate-cooldown-<id>.ts   # unix 到期时间
/data/instances/<id>/meta.json 可选字段:
  rotate_fail_streak: int   # 连续 rotate 失败次数
```

| 规则 | 值（默认，可 env） |
|------|-------------------|
| `ROTATE_FAIL_STREAK_MAX` | 2（连续 auto/耗尽 2 次进冷却） |
| `ROTATE_COOLDOWN_SEC` | 1800（30min） |
| 触发点 | `rotate_one` 返回非 0（含 v4_collision exhausted） |
| 冷却期内 | health-once **禁止** `AUTO_ROTATE` 调 rotate；手动 `POST /rotate` **仍允许**（清 cooldown 或忽略 cooldown） |
| 成功 rotate | `rotate_fail_streak=0`，删 cooldown 文件 |

**验收**：对故意同 IP 实例，auto 最多连触发 streak 次后日志 `auto-rotate suppressed (cooldown)`，30min 内 failures 可涨但**不再** stop/start 风暴。

### P0.3 缩短 start flock 范围（R4）

**文件**：`scripts/start-instance.sh`

| 现状 | 目标 |
|------|------|
| `flock` 包整脚本到结束 | 锁只包：**清 socket → 起 warp-svc → 确认存活**（≤15s） |
| register/connect/microsocks 在锁内 | **出锁后**再 register/connect/socks |
| 已存活 early-return 仍可占锁 | 存活检测在锁内极短路径后立即释放 |

注意：出锁后 register 与第二次 start 竞态 —— 保留「已 alive 则 skip 再起」；connect 失败不要长时间持锁重试。

**验收**：id0 做 unique 重试时，id1 `start-instance` 在 ≤20s 内能拿到锁并完成（不再 180s timeout）。

### P0.4 entrypoint 勿因瞬时全死自杀

**文件**：`entrypoint.sh` 监督环

| 现状 | 目标 |
|------|------|
| `alive < 1` → `exit 1` 整容器重启 | 连续 `ALL_DEAD_EXIT_STREAK`（默认 3）次且间隔 ≥30s 才 exit；或改为只 log + 尝试串行 start，**默认不 exit**（env `SUPERVISE_EXIT_ON_ALL_DEAD=0`） |

推荐默认：`SUPERVISE_EXIT_ON_ALL_DEAD=0`（破坏性过大，已证伪为放大故障）。

**验收**：人为 stop 全部 warp-svc 60s 内，容器 **不** restart；监督环逐个 start 恢复。

## P1 — 状态一致性

### P1.1 health-once 单飞

**文件**：`scripts/health-once.sh`、`scripts/health-loop.sh`、`scripts/rotate-instance.sh`

```bash
# health-once 开头
exec 8>"${PID_DIR}/health-once.lock"
if ! flock -n 8; then
  log "health-once already running — skip"
  exit 0
fi
```

| 调用方 | 行为 |
|--------|------|
| health-loop | 拿不到锁 → skip 本轮（已有 interval） |
| rotate 内部 | **删除**嵌套全量 `health-once`；改为 `_refresh_self_meta` 或只 `write_meta` + 可选轻量 `rebuild_healthy_from_meta` |
| membership API | 可 `flock -w 30` 等待一次刷新 |

**验收**：rotate 进行中 `ps` 最多 1 个 health-once；`healthy.json` 无空窗超过 1 个 interval。

### P1.2 禁止 rotate 嵌套全量 health-once

**文件**：`scripts/rotate-instance.sh`

去掉（或替换）所有：

```bash
SUPERVISE_RESTART=0 bash "${SCRIPTS_DIR}/health-once.sh"
```

替换为：

1. drain 时：只改本 id meta（已有）  
2. 成功/失败结束：`rebuild_healthy_json`（新 lib 函数：扫全部 meta，healthy+unique+eligible → backends，原子写）  
3. 不在 rotate 路径上 start 其它 id  

**验收**：rotate id=1 全程，id=0/2 的 backends 不被写成 `[]`。

### P1.3 failures 分轨

**文件**：`scripts/health-once.sh`、`lib.sh` write_meta

| 计数 | 用途 |
|------|------|
| `failures`（保留） | probe fail / 进程死 |
| `collision_streak`（新，meta） | 仅 v4 与它人冲突连续次数 |
| AUTO_ROTATE 触发 | probe/dead：`failures ≥ HEALTH_FAILURES`；撞 IP：`collision_streak ≥ COLLISION_ROTATE_THR`（默认 3） |
| 成功 unique probe | 两计数皆 0 |

**验收**：进程死 3 次会 restart start，但**不会**因 dead 误走「同 IP hard 链」；仅撞 IP 才走 collision rotate。

### P1.4 rebuild_healthy_json 与 meta 对齐

**文件**：`scripts/lib.sh`

```bash
rebuild_healthy_json() {
  # 扫 list_instance_ids
  # 条件: meta.healthy && meta.unique && is_pool_eligible && pid alive
  # 原子写 healthy.json
}
```

health-once 末尾、rotate 结束、membership 后都可调用。

**验收**：`/pool` members 与「meta healthy+pooled+unique+alive」集合一致（允许 ≤1 个 interval 延迟）。

## P2 — 体验与可观测

### P2.1 sticky 跟随健康

**文件**：`cmd/warppool/main.go`（选路 + 可选 health 钩子）、或 shell `rebuild_healthy_json` 后调小脚本

| 规则 | 行为 |
|------|------|
| sticky id ∉ backends 或 meta.healthy=false | 删除 sticky.json（或标记 inactive，选路当 null） |
| 日志 | `sticky cleared id=N reason=unhealthy|not-member` |

**验收**：sticky→id4，杀 id4 warp-svc 后 ≤1 个 health 周期，聚合不再优先 id4；`GET /pool` sticky 为 null。

### P2.2 /pool excluded 语义

**文件**：`cmd/warppool/main.go` GET `/pool`

| 现状 | 目标 |
|------|------|
| 凡不在 backends 的都进 excluded（含 healthy 未入 backends） | `excluded` 仅：`pooled=false` **或** `healthy=false`；临时 unique-lock skip 可标 `reason=transient` |
| healthy+pooled 却在 excluded | **禁止** |

### P2.3 日志降噪（已有 throttle，补全）

| 事件 | 要求 |
|------|------|
| auto-rotate suppressed | 每 id 每 cooldown 只打 1 次 info |
| start lock wait | debug 或 throttle |
| same-ip-unique accept | info 一条即可 |

### P2.4 回归测试

**文件**：`tests/smoke-selfheal.sh`（新）

可在旁路容器跑的检查（不依赖真换 IP 成功）：

1. **unit-ish**：构造 meta baseline= X，池内无冲突 → `_commit_changed_unique` 接受（可 source + mock v4_conflicts）  
2. **lock**：并行两个 `start-instance` 同 id，第二个等待后 ok 或 skip，不 socket bound  
3. **health 单飞**：并行两个 health-once，只有一个写 healthy.json（mtime/内容）  
4. **cooldown**：mock rotate fail → 第二次 AUTO 被 suppress  
5. **sticky clear**：写 sticky 后 meta unhealthy → rebuild 后 sticky 空

## Acceptance（现网）

部署 tip 后 1h 内：

| # | 检查 | 通过标准 |
|---|------|----------|
| A1 | `GET /health` | healthy ≥ 3/5（N=5 时），无持续 1/5 |

| A3 | docker logs | 无连续 `v4_collision exhausted` 风暴；有则伴随 cooldown suppress |
| A4 | docker logs | 无 `all warp-svc processes dead` 导致的容器重启环 |

## Risk

| 风险 | 缓解 |
|------|------|
| 接受 unique 同 IP 后「假换号」体感 | 仅 auto 路径接受；手动 rotate UI 仍可 hard；history 标 `same-ip-unique` |
| 关闭 all-dead exit 后僵尸容器 | 监督仍 start；告警靠 healthy&lt;1 持续 |
| rebuild_healthy 与 probe 竞态 | 单飞 health + 原子写 |
| cooldown 过长掩盖真故障 | env 可调；手动 rotate 旁路 |

- 多容器代替 netns
